# Корзина, оформление и заказы TIHO

Сайт и ChatGPT используют один модуль commerce, каталог и D1. Суммы считаются
целыми копейками, валюта приходит с сервера. Корзины, сводки, заказы, попытки и
результаты оплаты переживают перезапуск процессов. Заказ сохраняет снимки
названий, цен и количества; редактирование каталога их не меняет.

## Запуск и миграции

```bash
pnpm install --frozen-lockfile
pnpm db:migrate:local
pnpm db:seed:local
pnpm dev
```

Миграция `0001_stiff_dorian_gray.sql` добавляет семь commerce-таблиц и индексы,
не удаляет существующие данные. Seed не требуется при обновлении существующей
базы. Локальная D1 хранится в `backend/.wrangler/state`; перезапуск её не очищает.

Для MCP скопируйте `backend/.dev.vars.example` и `chatgpt/.env.example` в
соответствующие `.dev.vars`/`.env`, задайте одинаковый случайный секрет минимум
32 символа, затем `pnpm chatgpt:dev`. Для сайта без MCP секрет не нужен.
MCP слушает 127.0.0.1:8790, `/preview` — инструмент разработки, не ChatGPT.
Реальные значения env игнорируются Git и исключены из артефактов публикации.

## Платёжные режимы

| Настройка | Значение и поведение |
| --- | --- |
| APP_ENV | local, presentation, production |
| PAYMENT_ADAPTER | Только явно заданный internal_presentation в local/presentation включает адаптер; disabled запрещает checkout/оплату |
| PAYMENT_OUTCOME | success, failure, fail_once (первая попытка заказа неуспешна, следующая успешна) |
| PAYMENT_DELAY_MS | 0–10000, задержка только внутренней обработки |
| GUEST_ACCESS | local разрешён лишь в local; linked требует привязку из приватного плагина |
| STORE_ORIGINS | Точные origin сайта через запятую для проверки изменяющих browser-запросов |
| TIHO_MCP_SECRET | Общий секрет backend/MCP, только runtime, не включается в UI |
| MCP_AUTH_MODE | sites за приватной границей Sites; local только на loopback |
| DEV_MCP_USER | Синтетический пользователь локального MCP; не задаётся на Sites |

Ошибочная конфигурация не включает симуляцию как запасной режим. В production
адаптер отключён. В D1 payment_mode=internal_presentation; попытка проходит
pending → processing → internal_succeeded либо failed. API отдаёт нейтральный
succeeded, UI показывает сохранённый заказ. Финансовой проводки, bank transaction
ID или утверждения реального поступления денег нет.

Попытка и выбранный результат записываются до ответа. Обработка восстанавливается
при чтении по ready_at; очередей и process timers нет. После ошибки новая попытка
относится к прежнему заказу. После успеха повтор возвращает прежний результат.
При сетевой неопределённости клиент читает состояние, затем повторяет прежний
operationId. Банк, карты, почта, доставка, резерв, списание запасов, чеки и возвраты
не подключены. Интерфейс не утверждает, что эти действия состоялись.

Для проверки отказа остановите локальный API и запустите:

```bash
pnpm --filter @tiho/backend exec wrangler dev --local --port 8787 \
  --var PAYMENT_OUTCOME:fail_once --var PAYMENT_DELAY_MS:2500
PAYMENT_TEST_OUTCOME=fail_once node scripts/verify-checkout-browser.mjs
```

Обычный `pnpm dev:api` возвращает конфигурацию success. В UI нет переключателей
результата. Контакты проверок фиктивные: Покупатель TIHO, purchase@example.test.

## Подтверждение и повторы

Добавление требует существующий доступный товар и целое количество 1–99;
максимум 50 позиций. Наличие — статус каталога, точный остаток не выдумывается.
Новый operationId увеличивает количество; сетевой повтор прежнего ID возвращает
подтверждённый результат. Повтор ID с другими параметрами отклоняется.

Quote на 15 минут содержит контакты и версию корзины. При создании проверяются
версия, цены и наличие, включая проверку внутри D1 transaction. Изменённые
условия требуют новой сводки и подтверждения. Уникальная версия корзины защищает
от конкурирующих checkout. Ошибка записи откатывает весь batch, сохраняя корзину.
Очистка касается строго подтверждённой версии: более раннее параллельное изменение
блокирует оформление; более позднее добавление сохраняется в новой версии.
Повтор подтверждения возвращает уже созданный заказ.

## Сессии и связь сайта с ChatGPT

Sites проверяет пользователя и задаёт oai-authenticated-user-id на доверенной
границе. MCP HMAC-преобразует identity и обращается к backend с отдельным секретом.
Нельзя размещать MCP в режиме sites на публичном Worker, принимающем произвольный
identity header из интернета. Корзина принадлежит подтверждённому пользователю;
чужой cart/order/attempt/quote ID не даёт доступа.

Браузер использует HttpOnly, SameSite=Lax, Secure (в облаке) cookie на 30 дней.
В D1 хранится hash. Презентационный сайт получает cookie через кнопку перехода
из панели TIHO. Одноразовый код живёт 60 секунд, хранится как hash, возвращается
UI в _meta и не входит в текст tool result/контекст модели. Код передаётся во
fragment `/connect#code=…`, сразу удаляется из адреса и атомарно обменивается один
раз. Постоянного session token в URL нет. Закладки и reload заказа работают по cookie.

Сайт, MCP и iframe не рассчитывают на общие cookies/localStorage. UI вызывает
app.callServerTool. Selection/cart/quote/order публикуются через updateModelContext.
Видимая панель читает backend при фокусе и polling; скрытые панели прекращают
опрос и публикацию контекста. Запросы не перекрываются, одинаковые данные не
публикуются повторно; старые версии не заменяют новые.
Текстовый запрос суммы использует get_cart без обязательного открытия панели.

## Размещение и проверки

Используются прежние Vercel project и owner-private Sites project. Сайт проверяется
в preview с существующей Vercel Authentication; API — в env presentation того же
backend с прежней D1. Remote migration добавляет таблицы, remote seed не запускается.
Production-каталог и его доступ не меняются. После Vercel preview его точный origin
задаётся в STORE_ORIGINS backend и STORE_URL приватного MCP.

```bash
pnpm check
node scripts/verify-checkout-browser.mjs
node scripts/verify-checkout-recovery.mjs
node chatgpt/scripts/verify-checkout-browser.mjs
node chatgpt/scripts/verify-browser.mjs
```

Браузерные сценарии требуют agent-browser и работающие API/UI/MCP. Они используют
настоящую D1. Интеграционные тесты применяют миграции к отдельной D1, проверяют
гонки, rollback, доступ, изменение цен и повтор оплаты. Итоги и границы проверки:
[checkout-progress.md](checkout-progress.md). API и локальный MCP host сами по себе
не являются доказательством работы в ChatGPT.

Размещённый preview: https://tiho-store-4y58lcfiw-denis-projects-91ecd61e.vercel.app.
Владелец входит через Vercel, затем использует «Продолжить на сайте» в TIHO в
ChatGPT для получения связанной сессии. После этого сайт открывается напрямую,
корзина и заказы восстанавливаются по cookie.
